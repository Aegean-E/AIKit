# Core Services & API Abstractions

## 🛠️ Service Registry
AIKit's services are its gate and utility CLIs in `scripts/` plus the project CLI `aikit.py`. The gate CLIs import nothing from each other; `aikit_cli.py` imports `project_registry.py` and `aikit_parser.py`, whose grammar `aikit.py --help` loads alone because it imports no AIKit module at top level (ADR-180), and the opt-in `ui_contract.py` imports `project_gates.py` and `project_registry.py`. Those layers run in one direction with no cycle (PRINCIPLE-009 R5). The command table in `README.md` lists their flags and exit codes, and `codebase_map.md` lists their functions.

| Service | Responsibility | Gate it provides |
|---|---|---|
| `sync_principles.py` | Generates every Tier 1 file in `TIER1_TARGETS` and README's principle table from `GUIDELINES.md`; computes `--involved` and `--citing` | `--check`: freshness, token budget, cross-principle ADR check (PRINCIPLE-000 R3) |
| `update_knowledge_base.py` | Regenerates `codebase_map.md`; audits README (including every `python aikit.py <cmd>` against the CLI's declared subcommands), the ADR register, unfinished code and code structure (including assignment to another object's `_private` attribute) | `--check` (PRINCIPLE-005, -007, -009 to -011, -016) |
| `disruption_recovery.py` | Task ledger: checkpoints, resume, reset, track, commit-message validation; `--workspace <project>` uses that project's `.aikit/task_ledger.json` (ADR-120) | `--validate-commit`, `--track` (PRINCIPLE-002, -006) |
| `check_reachability.py` | Finds production functions with no production caller outside themselves and keys read but never written | exit 1 on either (PRINCIPLE-014 R7) |
| `check_secrets.py` | Scans staged changes, tracked files and agent memory for credentials; `--workspace <dir>` scans that repository instead, e.g. a project (ADR-121) | exit 1 on a finding or an unscanned surface (PRINCIPLE-019) |
| `check_test_budgets.py` | Measures unit and integration tier average durations against strict per-test ceilings | exit 1 on budget breach or test failure (PRINCIPLE-010 R6, PRINCIPLE-014 R3) |
| `aikit.py` (`aikit_cli.py`) | `new`, `attach`, `list`, `status`, `resume`, `checkpoint`, `complete`, `clean`, `guideline`, `check`, `fix`, `publish`, `delegate`, `ui init/begin/verify/allow/finish/abort/status`: the projects AIKit builds, each its own folder and git repository (ADR-119); `status --exit-code` makes dirty, conflicted, open-UI-task or unauditable trees a machine-readable failure; `check` pushes only with `--push`, so running Phase 4 never publishes (ADR-185); `fix` adopts a detected UI project with a test command and marks its contract required, and `check` validates a declared game mechanics contract; `check --strict` and `publish` refuse unresolved conflicts, open UI tasks and a missing `ui_required` contract; `publish` also runs the project's gates and test gate before uploading (ADR-153, ADR-155, ADR-161, ADR-163, ADR-166); `ui` bounds edits to one committed surface and proves what it renders when a project opts in (ADR-158, ADR-160) | exit 2 on a bad name or path, 1 on a failed request, with Why/Fix |
| `project_registry.py` | Library behind `aikit.py`: finds projects, detects each one's stacks and test command (`DETECTORS`), writes `.aikit/project.json` and `.aikit/decisions.md` | none; reached through `aikit.py` |

| `ui_proof.py` | The guard's pure mechanical proofs: sorted snapshot lines, removed-entry findings honouring allowed patterns, and hardcoded color/font literal findings outside declared theme paths (ADR-160) | none; reached through `ui_contract.py` |
| `project_gates.py` | A project's gates: test command, extras detected from its config (`EXTRA_GATES`), a declared `mechanics.test`, `project.json` `gates` overrides, built-in hygiene scan, guidelines check and secret scan; runs them in the project folder | `python aikit.py check <name>` exits 1 on any failed gate or no test gate (ADR-122) |
| `check_project_hygiene.py` | Scans a project's Python source and static assets: shell/system/exec, non-portable subprocess, unencoded `open()`, any `except` that only discards the error, absolute paths, third-party asset URLs. `--artifacts` adds git-decided delivery hygiene: root test modules (including ignored files and unittest's `test*.py`), untracked root source/output and tracked caches/build output (ADR-153, ADR-156) | exit 1 on a finding; built into `aikit check`; `--artifacts` is opt-in (ADR-137) |

| `subagent_delegate.py` | Runs one OpenCode sub-agent (roles = `.opencode/agents/*.md`) supervised, stdin closed, with a timeout; scrubs credential-shaped output on every report path; reports a ledger changed during the run | `aikit delegate` exits 1 on timeout or a changed ledger (ADR-128) |
| `reforge/` (Aegean Reforge) | Progressive Git history reviewer and safe repairer behind `aikit.py reforge` and `python -m reforge`: `start`/`settings`/`stop`/`resume` manage independent runs with configurable start/step/stop windows, `audit` writes the next window's review packet, `fix --findings` applies the host agent's answer, `run` does both, `runs`/`status`/`report` expose history; Python files go through the opt-in AST detectors and every other changed text file through `reforge/textdetect.py` (JSON/TOML parse, Markdown fence closure, committed conflict markers), while `reforge/review.py` writes the stage's complete net diff under `.aikit/reforge.reviews/` with credential spans redacted and validates the reviewer's JSON by path, line, evidence, exact-once replacement and stage overlap (ADR-230, ADR-232, ADR-249, ADR-253, ADR-263, ADR-266) | exit 1 on an operating failure; each project has its own resolved lock and state, so different projects audit concurrently while a second operation on one is refused; tests, gate or patch review roll repairs back; unrelated uncommitted paths are snapshotted, never staged, and a commit is refused only when a finding target was already dirty (`--allow-dirty` overrides); no model call, API key or subagent is used; `--push` is the only path that commits and pushes; AIKit's root is the only source and the former standalone repository is archived (ADR-248) |
| `idea_catcher/` (Idea Catcher) | Target registry, idea ledger, review ledger and generated matrix behind `aikit.py idea-catcher`, `python -m idea_catcher` and `python idea_catcher.py`: `validate`, `render`, `status`, `sync`, `ideas [--include-rejected|--include-duplicates]`, `tag`, `history`, `reviews`, `review-start/finish/abandon`, `revalidate`, `audit-claims`, `concepts`; its register is private, git-ignored data under `.idea-catcher/` at the AIKit root (ADR-246, ADR-252, ADR-264) | exit 1 on an invalid register or a failed strict check; writes stay under `.registry.lock`; delivered `IDEA-NNN` commits auto-register and refresh `MATRIX.md`; the collected ideas are never committed; rejected and duplicate rows leave the default listing but stay in the matrix |
| `project_ui.py` / `project_topics.py` / `project_media.py` / `project_artwork.py` | Project presentation policy behind `aikit.py ui-id`, `topics` and `media`: durable UI identifier, AI-chosen/validated GitHub topics (max 20), online image-model-rendered logo/social cards with exact title and category, commit-stamped screenshots with mandatory review, and approved-asset application to README and the AegeanWorks dossier (ADR-233..245) | read-only where a review is requested; no tag or asset is automatic; media apply writes only approved files |

| `dogfood.py` | Runs AIKit's CLIs as real processes in a sandbox: golden path, chaos, gates, `--help` budget. Its blast-radius fingerprint hashes git-status paths and their content, not every clean tracked file (ADR-154) | exit 1 on any failed track (PRINCIPLE-015) |

## 📋 Design Rules
1. A service is one module; a role with two or more implementations is declared as a `typing.Protocol` of 1 to 5 methods (PRINCIPLE-009 R1, R2).
2. Each service runs alone with the standard library (PRINCIPLE-011 R1); a shared import goes one direction only (PRINCIPLE-009 R5).
3. A failing service exits 1 with the remediation triad and never prints a traceback (PRINCIPLE-011 R5, R6).
